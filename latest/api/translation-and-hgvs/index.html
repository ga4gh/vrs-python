Translation and HGVS

Translates various external formats into VRS models.

Input formats: VRS (serialized), hgvs, spdi, gnomad (vcf) Output formats: hgvs and spdi for Alleles; no copy-number exporters.

USE_INSTANCE_DEFAULT module-attribute 

USE_INSTANCE_DEFAULT = TranslationDefault.INSTANCE

Use the translator instance setting for an omitted option.

TranslationDefault

Bases: Enum

Mark options that use the translator instance setting.

USE_INSTANCE_DEFAULT distinguishes an omitted option from an explicit None. For rle_seq_limit, the default uses the instance limit, while None means no limit. Enum members preserve their identity through copying and pickling.

to_spdi 

to_spdi(
    vo: Allele,
    namespace: str | None = "refseq",
    *,
    ref_seq_limit: int | None = 0,
    **kwargs: object,
) -> list[str]

Generate a list of SPDI expressions for VRS Allele.

If namespace is not None, returns SPDI strings for the specified namespace.

If namespace is None, returns SPDI strings for all alias translations.

If ref_seq_limit is specified, the reference sequence is included in the SPDI expression only if its length is at most the limit. Otherwise only the length of the reference sequence is included. If the limit is None, the reference sequence is always included. In all cases, the alt sequence is included. Default is 0 (never include reference sequence).

If no alias translations are available, an empty list is returned.

Requires an inline SequenceLocation with integer bounds and either a LiteralSequenceExpression or a ReferenceLengthExpression with integer length and a positive repeatSubunitLength. Unsupported model shapes are not validated before their fields are accessed.

SPDI and VRS use identical normalization. The incoming Allele is expected to be normalized per VRS spec.

For AlleleTranslator HGVS, SPDI, and gnomAD inputs:

hgvs_tools 

hgvs_tools() -> HgvsTools

Instantiate and return an HgvsTools instance

Returns:

Type Description
HgvsTools

Lazily initialized HGVS tools.

Convert HGVS expressions and coordinates.

HGVS uses 1-based positions; VRS uses interbase bounds. Omitting the accession::

HGVS                            VRS start        VRS end
g.100A>T                        99               100
g.100_101insT                    100              100
g.(100_110)_(200_210)del          Range([99,109])  Range([200,210])

Insertions use the boundary after the start residue for both bounds. For ranges, starts shift by one and ends stay unchanged. AlleleTranslator rejects uncertain ranges; use CnvTranslator for uncertain del/dup copy-number expressions.

With a configured data_proxy and accessible UTA database::

from ga4gh.vrs.extras.translator import AlleleTranslator

translator = AlleleTranslator(data_proxy)
try:
    allele = translator.from_hgvs("NC_000019.10:g.44908822C>T")
    expressions = translator.to_hgvs(allele, namespace="refseq")
finally:
    translator.hgvs_tools.close()  # Closes UTA, not the supplied data proxy.

Coding coordinates pass through c_to_n on import and n_to_c on export.
