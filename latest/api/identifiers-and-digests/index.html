Identifiers and digests

Serialize, digest, and identify GA4GH models.

For an Allele without cached IDs or digests, the main steps are (intermediate helper calls omitted)::

ga4gh_identify(allele)
+ allele.compute_ga4gh_identifier()
  + allele.compute_digest()
    + allele.ga4gh_serialize()
      + location.get_or_create_digest()  # identifiable child
      + state.ga4gh_serialize()          # inline value object
    + encode_canonical_json(...)
    + sha512t24u(...)

Given an Allele, call the public helpers::

from ga4gh.core import ga4gh_digest, ga4gh_identify, ga4gh_serialize

identifier = ga4gh_identify(allele, in_place="never")  # GA4GH CURIE
digest = ga4gh_digest(allele)  # digest component
serialized = ga4gh_serialize(allele)  # canonical JSON bytes

in_place="never" leaves the ID unchanged; "always" stores the result; "default" stores it only when the ID is None. Digests may still be cached.

To reuse any nonempty ID::

from ga4gh.core import VrsObjectIdentifierIs, use_ga4gh_compute_identifier_when

with use_ga4gh_compute_identifier_when(VrsObjectIdentifierIs.MISSING):
    identifier = ga4gh_identify(allele)

GA4GH_INVALID instead requires an ID matching the GA4GH pattern. ANY always calls the model identifier method, which may reuse cached IDs or digests. After editing an allele, refresh changed identifiable children first, then::

identifier = allele.get_or_create_ga4gh_identifier(
    in_place="always", recompute=True
)

VrsObjectIdentifierIs

Bases: IntEnum

Control when ga4gh_identify calls the model identifier method.

  • ANY: Always call the method (default).
  • GA4GH_INVALID: Call it when the ID is missing or syntactically invalid.
  • MISSING: Call it only when the ID is None or empty.

The default policy calls the model identifier method. That method may reuse an existing valid identifier or digest; this policy does not force recomputation. Where the source of inputs to ga4gh_identify are well controlled, for example when annotating a VCF file with VRS IDs, using MISSING can improve performance.

ga4gh_identify 

ga4gh_identify(
    vro: BaseModel,
    in_place: str = "default",
    as_version: PrevVrsVersion | None = None,
) -> str | None

Return a GA4GH identifier, or None for a non-identifiable object.

This function has three options for in_place editing of vro.id:

  • 'default': the standard identifier update behavior for GA4GH identifiable objects, this mode will update the vro.id field only when it is None
  • 'always': this will update the vro.id field any time the identifier is computed (compute behavior is controlled by the use_ga4gh_compute_identifier_when context)
  • 'never': the vro.id field will not be edited in-place, even when empty

The context policy may return an existing ID without computing one. When computation occurs, as_version selects legacy serialization and bypasses in-place ID updates; it does not override the context policy. Accepts a supported PrevVrsVersion member or its string value. Raises ValueError for other version values.

For example:

>>> from ga4gh.core import ga4gh_identify
>>> import ga4gh.vrs
>>> location = ga4gh.vrs.models.SequenceLocation(
...     start=44908821,
...     end=44908822,
...     sequenceReference=ga4gh.vrs.models.SequenceReference(
...         refgetAccession="SQ.F-LrLMe1SRpfUZHkQmvkVKFEGaoDeHul"
...     ),
... )
>>> ga4gh_identify(location)
'ga4gh:SL.4t6JnYWqHwYw9WzBT_lmWBb3tLQNalkT'

ga4gh digest algorithm

sha512t24u 

sha512t24u(blob: bytes) -> str

Generate a base64url-encode, truncated SHA-512 digest for given binary data

The sha512t24u digest is a convention for constructing and formatting digests for use as object identifiers. Specifically::

* generate a SHA512 digest on binary data
* truncate at 24 bytes
* encode using base64url encoding

For example:

>>> sha512t24u(b"")
'z4PhNX7vuL3xVChQ1m2AB9Yg5AULVxXc'

>>> sha512t24u(b"ACGT")
'aKF498dAxcJAqme6QYQ7EZ07-fiw8Kw2'
